# 꿀픽(swproject) 개발 로그

코드와 분리된 **개발 기록 전용 브랜치(`devlog`)** 입니다. 코드 브랜치의 히스토리와 섞이지 않도록 orphan 브랜치로 만들었습니다.

목적
- 다른 AI 모델(또는 사람)이 작업을 이어받거나 **검증**할 때 맥락을 바로 파악하게 한다.
- 나중에 "왜 이렇게 했지?"를 다시 찾을 수 있게 **문제 → 원인 → 해결 방안 → 해결 → 이유 → 검증**을 남긴다.

## 구성

| 경로 | 내용 |
| --- | --- |
| [INDEX.md](INDEX.md) | 모든 이슈 한눈에 보기 (번호·상태·브랜치·커밋) |
| [LOG_TEMPLATE.md](LOG_TEMPLATE.md) | 새 로그를 쓸 때 복사하는 양식 |
| [PROMPTS.md](PROMPTS.md) | 다른 AI에게 그대로 붙여 넣는 프롬프트 (검증·로그 작성·이어서 작업) |
| [VERIFY.md](VERIFY.md) | 테스트·검증 실행 방법 (격리 DB, Windows 주의점) |
| `logs/YYYY-MM-DD-<주제>.md` | 작업 세션별 상세 로그 |

## 규칙

1. **한 이슈 = 한 항목.** 번호(`#NN`)는 INDEX.md에서 이어서 매긴다. 재사용 금지.
2. 항목에는 반드시 다음을 쓴다: 문제점 / 원인 / 해결 방안(검토한 선택지) / 해결(적용 내용·파일·커밋) / 왜 그렇게 해결했는지 / 검증 / 남은 과제.
3. **추측과 확인한 사실을 구분**한다. 확인하지 못한 것은 `가정:` 또는 `미확인:`으로 표시한다.
4. 커밋 해시와 브랜치를 적는다. 코드가 바뀌면 로그도 같은 날 갱신한다.
5. 비밀번호·API 키·토큰·개인정보는 절대 적지 않는다(값 대신 환경변수 이름만).
6. 상태 값: `해결` / `부분 해결` / `미해결` / `보류` / `확인 필요`.
