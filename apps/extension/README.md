# Chrome 확장

> 최신 실제 API 연결·Docker UI 실행은 [프론트 · 백엔드 통합 실행](../../docs/FRONTEND_INTEGRATION.md)을 따릅니다. 기본 API는 실제 로컬 백엔드이며 화면 목업은 명시적으로 선택합니다.

WBS 담당: 서지웅

Chrome MV3 확장 프론트엔드. React 18 + TypeScript + Vite. 실제 로컬 백엔드 API를 기본으로 사용한다.

## 실행
```bash
cd apps/extension
npm install
npm run build          # 타입 검사 + dist/ 생성
```
Chrome `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램을 로드합니다" → `apps/extension/dist` 선택. Chrome 116 이상.

확장 설치 없이 화면만 보려면:
```bash
npm run preview:sidepanel   # http://localhost:5174/preview.html
```
`?url=` 로 분석할 페이지를 바꾼다(프린터 상품 / 땅콩 식품 / 상품 아님 링크가 화면에 있음). 미리보기는 localStorage를 쓴다.

## 환경변수
`.env.example` 참고. `VITE_API_BASE_URL`은 실제 API 주소이며 기본값은 `http://127.0.0.1:8000`이다. `VITE_USE_MOCK_API=true`를 명시했을 때만 `src/shared/api/mock.ts`를 사용한다. API 응답을 받지 못해도 목업으로 자동 전환하지 않는다.

## 변경 이력 (2026-11-26)

이번 커밋은 확장뿐 아니라 같은 화면 규칙을 쓰는 **모바일 앱**과, 화면에 필요한 **백엔드(API·추천·분석 작업자)** 변경을 함께 담는다. 확장과 모바일은 같은 규칙을 쓰도록 같은 내용의 파일을 둔다(`shared/allergens.ts`, `shared/validation.ts`, `shared/pageFilter.ts` 등은 두 앱이 같은 내용).

### 1. 추천 결과 화면
- **탭 없이 한 화면에서 스크롤**: 알레르기 경고 → **최저가 추천 상품** → **AI 추천 상품** → **해외 추천 상품** → **중고 추천 상품** 순서로 보여준다(`shared/ui/ResultView.tsx`, 모바일 `ui/ResultView.tsx`).
- **최저가 추천**: 공개된 AI 추천 후보(중고·해외 제외)를 가격 낮은 순으로 정렬. 통화가 다르면 환율 없이 비교할 수 없으므로 원화 상품을 먼저, 해외 통화 상품은 통화별로 뒤에 둔다(`lowestPriceItems`).
- **해외 추천 상품 구역 신설**: 원화가 아닌 가격(USD·EUR 등)의 새 상품은 AI 추천에 섞지 않고 별도 구역에 최대 3개. "배송비·관세·전압(110V/220V)을 확인해 주세요" 안내. 해외상품 포함을 켰는데 없으면 "비슷한 해외 판매처 상품이 없어요".
- **중고 추천 상품**: 중고는 AI 공개 개수(무료 3개)에 넣지 않고 별도 구역에 최대 3개. 중고상품 포함을 켰는데 없으면 "지금 구매할 수 있는 중고 매물이 없어요".
- **AI 추천 개수**: 무료 회원 3개 공개(+잠금 2개), 프리미엄 5개. 버튼·결제 완료 문구를 "추천 5개"로 변경.
- **비슷한 상품이 없을 때**: 분석은 됐지만(상품/식품 판별됨) 추천이 0개면 "비슷한 상품을 찾지 못했어요"를 보여준다. 정말 상품 페이지가 아닐 때만 "이 페이지에는 추천할 상품이 없어요".

### 2. 알레르기 경고 (프론트 조건)
- 규칙은 `shared/allergens.ts`의 `warningsForDomain` 하나로 확장·모바일 모든 화면(사이드 패널, 결과 화면, 플로팅 카드, 상단 "꿀픽 · 알레르기 주의")이 같이 쓴다.

| 분석 결과(`selected_domain`) | 알레르기 경고 |
| --- | --- |
| `food` (식품) | 백엔드가 보낸 경고 중 **식품 알레르기 항목만** 표시 |
| `product` (일반 상품) | **표시하지 않음** (식품·피부 모두) |
| 모름(`null`) | 표시하지 않음 |

- 알레르기가 여러 개면 **경고창 하나**에 모은다(`allergyNotice`). 제목은 1개면 "땅콩 알레르기 주의", 여러 개면 "알레르기 주의 · N개 항목".
- 문구를 자연스럽게 변경: 성분표를 읽지 못하면 "알레르기 성분표를 인식하지 못했어요. 안전하다는 뜻은 아니에요." (이전: "식품인지 확인하지 못해 …").
- 추천 상품이 0개여도 식품 페이지의 알레르기 경고는 반드시 보여준다(이전에는 빈 화면으로 바뀌며 경고가 사라짐).

- 백엔드 성분 검출표(`services/recommendation/allergens.py`)와 API 식품 코드표(`services/api/kkulpick/extensions.py`)에도 새 식품 코드 추가(파인애플→사과, 망고스틴→망고 오탐 제외).

### 4. 상품 페이지 인식 (`shared/pageFilter.ts`, `shared/pageProduct.ts`)
- **등록되지 않은 쇼핑몰도 분석**: 예전에는 주소에 `products`·`goods` 같은 단어가 정확히 있어야 했다(나이키 `/kr/t/…`, 아디다스, 자라, 애플은 분석 안 됨). 이제 로그인·결제 등 민감한 주소만 빼고 모두 "페이지 안 상품 표시 확인" 단계로 보낸다.
- **상품 표시가 없는 국내 쇼핑몰 보조 판단** (`hasCommerceSignal`): JSON-LD·`og:type=product`가 없는 디바이스마트·컴퓨존·모다아울렛 같은 곳은 ① 상품 상세 주소(`goods/product/item/detail/view`, `ProductNo=`, `no=`) ② 바로구매/구매하기/장바구니 버튼 ③ 가격(`560,000원`, `115,000`)이 **모두** 있으면 상품 페이지로 본다. 목록·검색·카테고리·장바구니·주문·이벤트·게시판·리뷰 주소는 제외.
- **식품 판단 힌트** (`pageDomain`): 페이지의 상품명·카테고리·경로(breadcrumb)·제목으로 식품이 확실하면 분석 요청에 `selected_domain=food`만 보낸다(페이지 주소·상품명은 보내지 않음). 화면 OCR이 리뷰 문장을 상품명으로 읽어 식품을 일반 상품으로 판단하던 문제를 막는다. 다른 말에 섞이기 쉬운 한 글자(빵·떡·껌·햄·쌀)는 쓰지 않고, "오픈소스·소스코드", 전자·패션 상품 단어(아두이노, CPU, 프린터, 패딩 등)가 있으면 식품으로 보지 않는다. 애매하면 보내지 않고 서버가 판단한다.

### 5. 플로팅 카드 (`content/Floating.tsx`, `content/drag.ts`)
- **상품 페이지에서만** 띄운다. 분석 중에는 "꿀픽 분석 중", 실패하면 "분석하지 못했어요 · 눌러서 다시 시도", 추천이 있으면 상품 카드, 식품 알레르기가 있으면 경고 카드. 상품 페이지가 아니거나 추천·경고가 모두 없으면 띄우지 않는다.
- **끌어서 옮기기**: 5px 넘게 움직이면 끌기, 짧게 누르면 사이드 패널 열기. 옮긴 위치는 `chrome.storage.local`(`kp.floating.position`)에 저장되고 창 크기가 바뀌면 화면 안으로 맞춘다. 모바일도 같은 동작(PanResponder, 웹에서 끌기 직후 누르기 무시).
- 사이드 패널이 열려 있으면 숨긴다(기존과 같음).

### 6. 분석 흐름 (`background/index.ts`)
- **비회원도 분석**: 로그인하지 않아도 분석한다. 기기별 무작위 키(`kp.guestKey`, 64자)를 `X-Guest-Key` 헤더로 보내고, 서버는 기본 설정(알레르기 없음, 중고·해외 제외, 무료 개수)으로 추천한다. 비회원 사이드 패널에도 분석 결과를 보여주고 위에 로그인 안내를 붙인다. "상품 추천" 스위치 설명도 회원과 같게 변경.
- **같은 페이지 중복 분석 방지**: 쇼핑몰은 로드 중 URL 변경·로드 완료 이벤트가 여러 번 와서 분석을 여러 번 접수하고 서로 취소했다(취소돼도 Vision 처리는 계속돼 실제 분석이 밀리고 90초 시간 초과). 같은 URL이 진행 중이거나 결과가 있으면 다시 접수하지 않는다. 다시 시도·로그인·설정 변경 때만 새로 분석.
- 로그인 직후 회원 정보(`/v2/me`)를 못 받으면 조용히 로그아웃 상태로 남지 않고 "로그인은 됐지만 회원 정보를 불러오지 못했어요" 오류를 보여준다(`sidepanel/session.tsx`).

### 7. 설정·회원 정보
- **해외상품 포함 on/off** 추가(중고상품 포함 아래). 기본 켜짐. 끄면 해외 판매처 상품을 추천하지 않는다. 비회원은 꺼짐으로 표시되고 실제로도 해외 상품을 받지 않는다.
- **키·몸무게·발 사이즈** (선택) 입력을 회원가입·개인정보 수정에 추가. 범위: 키 50~250cm, 몸무게 10~300kg(소수 첫째 자리), 발 사이즈 150~350mm(정수). 비우면 삭제. 마이페이지에 "키 172.5cm · 몸무게 미입력 · 발 270mm"로 표시(`shared/validation.ts`, `BodySizeFields`).
- 회원 탈퇴 링크 버튼의 기본 테두리 제거.

### 8. 고객상담 종료 처리 (`sidepanel/screens/more.tsx`, 모바일 `app/support.tsx`)
- 메시지와 함께 상담 상태를 3초마다 확인(`GET /v2/support/conversations`). 상담원이 종료하면(`resolved`/`closed`) 대화 끝 가운데에 `- - - 상담이 종료되었습니다. - - -`, 입력창·전송 버튼 비활성화, 상태 "상담 종료".
- "새 상담 시작하기" 버튼으로 새 상담을 연다. 다시 들어왔을 때 마지막 상담이 종료 상태면 종료된 채로 보여준다(예전에는 몰래 새 상담을 만들었다).
- 전송 중 종료되면 서버의 `CONVERSATION_CLOSED`를 받아 종료 상태로 바꾼다. 좁은 화면에서 "전송" 버튼이 두 줄로 깨지던 문제 수정.

| `services/dev_runtime/analysis_worker.py` | 식품 판단 단어를 엄격하게(한 글자 단어 제외, "오픈소스"·전자·패션 단어는 식품 아님), 경고 문구 "알레르기 성분표를 인식하지 못했습니다" |

**적용 방법**: DB 마이그레이션이 2개 추가됐으므로 `python migrate.py`(Docker는 `migrate` 서비스를 `--build`로 다시 실행)를 돌려야 한다. 추천 서비스·분석 작업자 컨테이너는 재시작(분석 작업자는 이미지 다시 빌드)해야 새 코드가 적용된다.

### 확인한 것 / 남은 것
- 확인: 확장 빌드·타입 검사, 모바일 타입 검사·lint, 목업 미리보기 화면, 로컬 실제 API로 회원·비회원 분석·해외/중고 구역·상담 종료·프로필 저장, 실제 Chrome에서 쿠팡·디바이스마트·컴퓨존·모다아울렛 페이지 판별.
- 남은 것: 백엔드 pytest(DB 통합 테스트)는 이 PC에 pytest가 없어 실행하지 못함. 모바일은 실제 기기 화면 확인 전. 로컬 카탈로그에 식품이 1개뿐이라 식품 페이지는 대부분 "비슷한 상품을 찾지 못했어요"가 나온다(데이터 문제).

## 목업 데이터 확인 팁
- 결제 실패 화면: 개발자 도구에서 `kp.mock.paymentFail` 값을 true로 저장(미리보기는 `localStorage.setItem('kp.mock.paymentFail','true')`).
- 상담 종료 화면: `kp.mock.supportResolved` 값을 true로 저장하면 상담원이 상담을 종료한 상태가 된다.
- 목업 계정·기록은 `kp.mock.db` 키에 저장된다. 실제 개인정보를 넣지 않는다.

## 미검증
- 실제 Chrome에서는 쇼핑몰 페이지 판별·플로팅 "분석 중"/결과 카드까지 확인했다. 최신 빌드 전체 흐름은 확장 새로고침 후 다시 확인이 필요하다.
- 실제 API 연결 검증 범위는 [통합 실행 문서](../../docs/FRONTEND_INTEGRATION.md)의 자동 검증과 GitHub Actions 결과를 확인한다.
