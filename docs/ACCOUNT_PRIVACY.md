# 계정별 화면 데이터와 가입 입력 검증

## 변경 사항

- 아이디는 영문·숫자 4~16자이며 공백은 허용하지 않는다. 공백을 몰래 지우지 않고 즉시 안내한다. 로그인에서도 임의 trim을 제거했다.
- 비밀번호는 서버와 같은 8~128자 기준으로 가입·변경 중 피드백을 제공한다. 비밀번호 확인 불일치도 즉시 안내하며 서버 검증은 계속 유지한다.
- 바로가기는 `kp.user.<서버 user_id>.shortcuts`로 기기 내부에 계정별 저장한다. 기본 제공/내가 저장을 구분한다. 비회원은 기본 목록을 이용하지만 개인 저장은 로그인 후 가능하다.
- 기존 공통 키 `kp.shortcuts`의 소유자는 식별할 수 없어 특정 계정으로 자동 이관하지 않는다. 기존 값은 삭제하지 않지만 새 계정 목록에서 읽지 않는다.
- 최근 방문은 별도 저장하며 자동으로 바로가기에 추가하지 않는다. 앱 안에서 직접 연 주소와 모바일 브라우저의 탐색만 기록한다. 확장 프로그램은 Chrome 전체 방문 기록을 수집하지 않는다.
- 방문 목록은 최대 50개, 30일로 제한하고 다음 읽기에서 만료 항목을 정리한다. 검색 매개변수·fragment는 저장하지 않으며 로그인·결제 등 민감한 경로는 제외한다. 사용자명/비밀번호가 포함된 URL은 허용하지 않는다.
- 마지막 페이지는 사용자가 `마지막 페이지 다시 열기`를 눌러 복구한다. 로그인 직후 자동으로 외부 사이트를 열지 않는다. 폼 입력, 스크롤 위치, 외부 쇼핑몰 로그인 쿠키까지 복구하는 기능은 아니다.
- 로그아웃은 로컬 개인 저장을 지우지 않지만 다른 계정/비회원에게 표시하지 않는다. 탈퇴 성공 후 해당 계정의 로컬 바로가기·방문 기록을 삭제한다.
- 계정 전환 시 화면 상태를 재생성하고 늦은 회원 조회 응답을 폐기한다. 확장 분석 캐시는 인증 세션별로 검사하며 계정 변경 시 초기화한다.

## 저장·보안 범위

개인 바로가기·방문 기록은 이 기기의 앱 저장소에만 저장하며 다른 PC나 확장/모바일 간 자동 동기화하지 않는다. 서버의 회원·상담·분석 이력과는 구분된다. 같은 OS 계정의 로컬 저장소를 직접 읽을 수 있는 사람까지 막는 암호화 격리는 아니다.

실제 API 비밀번호는 scrypt+무작위 salt, 세션 토큰은 SHA-256 해시로 DB에 저장한다. 요청 검증 오류는 입력값을 반환하지 않으며 회원 API에 요청 제한이 있다. 모든 v2 API는 no-store이며 UI 프록시에 nosniff, no-referrer, SAMEORIGIN을 적용한다.

Chrome의 유출 비밀번호 경고는 알려진 유출 로그인 정보와 일치할 때 나타날 수 있다. 프로젝트 유출의 증거로 단정할 수 없으며 경고를 끄거나 우회하지 않는다. 노출된 비밀번호는 서비스별 고유한 비밀번호로 변경한다.

남은 배포 보안: 외부 서비스 HTTPS 구성, 네이티브 인증 토큰의 OS 보안 저장소 이전, 웹 인증의 HttpOnly 쿠키/CSRF 설계, 전체 침투 점검. 현재 웹/앱은 기존 bearer 토큰 저장 방식을 사용한다. 실제 쇼핑몰 쿠키는 꿀픽 계정과 별도의 브라우저 저장 영역이므로 계정 전환으로 쇼핑몰까지 로그아웃된다고 보장하지 않는다.
