## 문제점
기존 일지는 구현 커밋 중심이라 11월 22일 읽기 전용 점검이 빠졌다. 또한 개발 시작 이전 문서 제작을 포함할지 범위가 명확하지 않아 누락 재검토 중 사용자가 “실제로 개발시작부터만”이라고 정정했다.

## 원인
코드 작성·배포와 점검 보고는 다른 활동이며, 과거 통과 기록 뒤에 다른 변경이 들어오면 최신 상태가 달라질 수 있다. 기록 범위를 기준 없이 넓히면 개발 이전 설계/발표자료까지 혼합된다.

| 11월 4일 이후 구현·수정·검증만 추적 | 코드 이력과 사용자 범위에 맞음 | 근거 불명 활동은 별도 표시 필요 | 채택 |

## 해결 (적용 내용)
- 11월 22일 GPT 보고는 당시 main 기준 `e7f7007`을 읽기 전용으로 점검한 활동이다. OCR→추천→DB 저장 성공과 UI/관리자 테스트 중단을 분리했으며 그 점검에서 수정·병합하지 않았다.
- 당시 추천 경로가 HashEmbedder/RuleRanker·요청별 메모리 재색인·영역별 최대 1,000개 목록이라는 점을 확인했다. 이는 파일의 `InMemoryVectorIndex`, `reindex()`, 10회×100건 조회 코드로도 대조했다.
- 과거 보고에는 관리자 API/화면 불일치와 오래된 버튼 선택자 등의 문제가 있었다. 이번에는 모든 당시 UI 증상을 다시 재현한 것이 아니므로 역사적 점검 보고로만 기록한다. 해결 완료를 주장하지 않는다.
- 11월 23일 사용자 요청에 따라 maintest에서 영속 임베딩을 연결한 후속 작업은 기존 #43이며, 다른 AI의 이후 UI/관리자 수정과 구분한다.
- 이번 누락 검토로 #44~#46을 추가하고 이 읽기 전용 점검도 #47로 보완했다. `GPT_COVERAGE.md`에 코드 작업과 일지 대응표를 추가했다.
- **실제 코드 개발 시작은 저장소 최초 커밋 `4551d6d`의 2026-11-04로 잡았다. 10월 설계·정규화·편집용 ERD·발표자료 제작은 이번 devlog 범위에서 제외했다.** 개발 이후의 감사 보고서는 실제 코드 수정의 증거로만 참조한다.

## 왜 그렇게 해결했는지
점검 활동을 누락하지 않으면서도 발견한 문제를 수정 성과로 바꾸지 않기 위해서다. 사용자가 정한 시작 범위를 우선해 코드 개발 이전 산출물을 추가하지 않았다.

## 검증
- 이전 GPT의 2026-11-22 23:44(KST) 점검 보고를 다시 확인했다. 당시 Actions 240건 검토 보고와 UI 실패 기록은 과거 점검 근거이며 이번 실행 수치가 아니다.
- `e7f7007`의 추천 HTTP와 분석 작업자 코드를 직접 읽어 메모리/상한 경로를 재확인했다. 현재 maintest가 여전히 그 코드라고 주장하지 않는다.
- 이번 재검토에서는 커밋/파일/행, 개발일지 양식·상대 링크·새 번호, 기존 문서 변경 범위를 확인했다. 새 일지·대응표·INDEX만 devlog에 반영한다.
- #44의 과거 5개 CI 성공 상태도 원격에서 재확인했다. 서비스 테스트와 취약점 스캔은 새로 실행하지 않았다.

이번 보완에서는 과거 서비스 테스트를 재실행하지 않았다. 고정 커밋의 코드·기록·참조를 대조했으며 아래 한계를 포함한다.

## 남은 과제 / 주의
- GPT 원 작성 여부가 확인되지 않는 `4b1f5fc`~`2c65ccd`, 관리자 가입 원형 등은 계속 제외한다. 저장소 계정명/브랜치명만으로 GPT로 귀속하지 않는다.
