## #69 관리자 웹 제휴 링크 우회 저장 — 해결
- 문제: 서버가 허용 목록 밖 제휴 URL을 422로 거부하면 `https://store.example.test/redirect?url=<원래>`로 감싸 재저장(409 경로도 같음). 목록은 이를 다시 풀어 보여 줘서 관리자는 원래 주소를, 사용자는 깨진 링크를 받음.
- 해결(`apps/web/pages/affiliate/index.js`): 감싸기 제거. 409(이미 있는 제휴를 새로 등록)는 서버의 현재 버전으로 **원래 URL 그대로** 한 번 재시도. 422는 "HTTPS인지, 서버 허용 목록(AFFILIATE_URL_HOSTS)에 등록됐는지 확인" 안내. 목록은 서버에 저장된 주소를 그대로 표시(풀기 함수 삭제).
- 왜: 서버 검증을 화면이 우회하면 안 되고, 관리자가 보는 링크와 사용자가 받는 링크가 같아야 잘못 저장된 링크를 찾을 수 있다.
- 검증(격리 UI 스택: API 58000 + 웹 53000, 내장 브라우저): 관리자 로그인 → 새 제휴 등록
  - `https://www.coupang.com/...`(허용 목록 밖): PUT **1회 422**, 감싼 재시도 없음, 안내 문구 표시
  - `https://store.example.test/aff/ui-69`: PUT 200, 목록에 저장된 주소 그대로 표시, DB에 감싼 URL 0건
- 운영 참고: 이전 버전으로 이미 감싸 저장된 행이 있을 수 있음 → 목록에서 `store.example.test/redirect?url=`이 보이면 실제 제휴 URL로 수정. 운영 서버 `AFFILIATE_URL_HOSTS`에 실제 제휴 호스트 등록 필요.

## #71 임베딩 작업이 강제 종료로 시도 상한에 닿으면 멈춤 — 해결
- 원인: `claim_many`가 가져갈 때 `attempts`를 올림 → 같은 묶음에서 워커가 8번 죽으면 `attempts>=8`, `last_error` 없음 → 가져가지도(`attempts<8` 조건), `--requeue-failed`로 살리지도(`exhausted:` 조건) 못함.
- 해결(`embedding_worker.py`): `park_lost()` — 임대가 끝났고 시도 상한에 닿은 작업을 `exhausted:WorkerLost`, `available_at=infinity`로 보류(가져가기 전에 매번 실행). `pending_counts`의 보류 수에 잡히고 `--requeue-failed`로 되살아남. 문서 갱신.
- 테스트: `test_job_whose_worker_kept_dying_is_parked_and_requeueable`.
