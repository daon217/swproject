## 새 문제

### #62 Vision 성분 정제가 알레르기 근거를 지운다 — 치명(안전)
원인 (`kkulpick_vision/app/vision/ocr_engine.py`):
- 445줄 `len(item) < 2` 제외 → 한 글자 알레르기(밀·게·잣·굴) 삭제.
- 409~413줄: 괄호 안이 **알레르기 단어 하나일 때만** 보존, 나머지 괄호는 통째로 삭제 → `(밀:미국산)`, `(대두유)`, `(우유, 대두)` 같은 가장 흔한 표기가 사라짐.
- 449줄 `endswith("산") and len<=4` → `아황산`(3글자) 삭제(원산지 제거 의도).
- 453줄 "제조시설"·"알레르기" 포함 토큰 삭제 → 혼입 표시 소실. 워커는 혼입 원문을 따로 전달하지도 않음.
영향: 사용자 화면에 "알레르기 성분 없음"처럼 보이는 결과가 나올 수 있다(경고 누락).
해결 방안: (A) Vision은 **원문 줄을 보존해 함께 반환**(`ingredients_raw`, `cross_contact_raw`)하고 알레르기 판정은 추천 쪽 `split_ingredients`(괄호 내용 평탄화)로 일원화 — 권장. (B) 정제 규칙 보수: 1글자 알레르기 예외, 괄호 내용 평탄화, 원산지 패턴만 제거. 회귀 테스트로 위 표를 고정.

### #63 화면 1장 캡처로는 성분표가 거의 안 잡힌다 — 중요(설계)
- 확장은 보이는 화면만 캡처하고, 워커는 그 1장을 `is_last_frame=true`로 보낸다. 상세페이지 성분표는 대부분 화면 아래쪽이라 `analysis_unavailable`가 일반적인 결과가 된다.
- Vision의 15프레임 스트리밍 설계와 실제 연결이 맞지 않는다.
- 해결 방안: 스크롤 캡처 여러 장(또는 전체 페이지 캡처)을 순서대로 보내는 계약으로 맞추기 / DOM 텍스트(content script)로 성분 영역을 먼저 찾고 OCR은 보조 / 카탈로그(수집기 성분, #32)를 1순위로.

### #64 Vision 작업 예외 시 세션이 'processing'에 머문다 — 중요
- `process_frame_task`·`extract_metadata_fallback_task`에 예외 처리가 없다. OCR·디코딩 중 예외가 나면 상태가 끝나지 않아 워커가 90초를 다 기다린 뒤 성분 없이 진행한다(원인 정보 없음).
- 여러 프레임이 동시에 처리되면 `analysis_unavailable`와 `success`가 서로 덮어쓸 수 있다(마감 전 상태 재확인 없음). 1장만 보내는 현재 연결에선 드묾.
- 해결 방안: 태스크 try/except → `status=error` 마감, 마감은 `processing`일 때만(WATCH/Lua).

### #21 (기존) Vision 캐시 키가 이미지 앞 4096자 — 경미 → 중요로 상향
- `tasks.py:126, 278` `md5(b64[:4096])`. init과 frame이 같은 이미지인지 판별하는 용도라 지금 연결(같은 이미지 2번)에선 맞게 동작하지만, 크기·상단이 같은 다른 캡처를 같은 세션에서 보내면 **다른 이미지의 성분 결과를 재사용**한다. #63을 고쳐 여러 장을 보내기 시작하면 바로 드러난다. 해결: 전체 바이트 sha256.

### #65 추천 쪽 성분 분리의 작은 누락 — 경미
- `split_ingredients('원재료명: 게, ...')` 첫 토큰이 `원재료명: 게`라 한 글자 매칭(게) 실패.
- `밀 함유`가 공백 제거 후 `밀함유`가 되면 밀(1글자 동의어)을 못 잡음(`대두함유`는 잡힘).
- 해결 방안: 머리말(원재료명/알레르기 유발물질 등) 제거, `함유`·`포함` 접미사 분리 후 매칭.
