## 문제점
사용자는 기존 devlog 양식에 맞춰 “그동안 GPT로 했던 것만” 올리도록 요청했다. 저장소에는 팀원 코드와 Claude 후속 작업이 섞여 있어 모든 커밋을 GPT 성과로 간주할 수 없다. 당시 테스트 성공도 현재 서비스 전체가 완성됐다는 뜻이 아니다.

## 원인
기존 devlog에는 Claude 작성 일지가 있었고 GPT 작업은 주로 과거 대화·PR·코드 커밋·로컬 Codex 체크포인트에 분산돼 있었다. 커밋 작성자 계정이나 `codex`라는 브랜치명만으로 AI를 확정할 수 없다.

## 해결 방안 (검토한 선택지)

| 저장소의 모든 변경을 한꺼번에 GPT 기록으로 정리 | 빠름 | 팀원·다른 AI 성과 오귀속 | 미채택 |
| GPT 대화와 코드/PR/로컬 체크포인트를 교차 확인 | 귀속과 검증 범위를 설명 가능 | 근거 부족 작업은 남음 | 채택 |

## 해결 (적용 내용)
- 초기 환경부터 임베딩 연결까지 10개 주제 일지(#34~#43)와 이 범위 일지를 작성했다. 모든 파일 날짜는 회고 작성일이며 실제 작업 시기는 별도로 적었다.
- `LOG_TEMPLATE.md`의 문제점·원인·선택지·적용·이유·검증·남은 과제 구조를 사용했다. 선택지 비교는 회고 분석이며 당시 모든 대안을 실험했다는 주장이 아니다.
- INDEX에 작성 AI와 과거 완료 범위를 추가했다. 기존 Claude 일지·OPEN_ISSUES의 현재 판정은 변경하지 않는다.
- 과거 기능 구현의 한계는 기존 미해결 이슈를 연결한다. 이번 문서 정리를 새로운 코드 수정이나 이슈 해결로 표기하지 않는다.
- Firebase 관련 질문은 초기 DB 일지의 설계 논의에 포함했다. 새로운 DB 비교 실험이나 전환 작업으로 기록하지 않는다.

- 2026-11-24의 Claude 공동 작성 표시가 있는 관리자 포팅·재시도 제한/배치·검색 및 오류 처리·브랜드/카테고리 임베딩·확장 정보 보류·신선도 check-in 등의 후속 수정.
- 원 작성 AI를 확정하지 못한 관리자 가입 원형(`855192d`, `52c486e`)과 11-23의 `4b1f5fc`~`2c65ccd` 후속 구간. 코드가 없다는 뜻이 아니라 이번 GPT 귀속 기록에서 제외했다는 뜻이다.
- 팀원 작성 기능을 GPT가 처음부터 만들었다는 주장, 검증 자료 없는 배포/실결제/품질/성능 완료 주장.

## 왜 그렇게 해결했는지
개발일지는 다음 작업자가 실제 상태를 판단할 근거여야 한다. 모델 구분, 작업 시점, 코드 변경과 설계 논의, 당시 테스트와 현재 판정을 나누면 과거 성공 기록 때문에 현재 미해결 문제가 가려지지 않는다.

## 검증
- 기존 README·PROMPTS·LOG_TEMPLATE·INDEX·OPEN_ISSUES·VERIFY와 기존 일지 목록을 확인했다.
- 개별 일지의 코드 파일·행을 해당 커밋에서 확인했다. GitHub Actions 41867281673, 44050527427, 44221228764, 44230941340, 44242147154, 45095253284는 회고 작성 시 성공 상태를 다시 확인했다.
- 이번 작성에서는 과거 서비스 테스트를 재실행하지 않았다. 개별 결과는 당시 PR/실행 로그의 결과이며, 실행별 합계를 서로 더하지 않는다.
- 문서 양식·링크·참조·번호와 diff 검사를 수행한 뒤 devlog에만 반영한다. 코드 브랜치의 변경은 포함하지 않는다.

## 남은 과제 / 주의
- 모든 과거 채팅 원문을 완전히 복원한 것은 아니다. 이 기록은 확인 가능한 범위의 회고이며 빠진 작업은 근거 확인 후 별도 일지로 추가한다.
- 최신 운영 판단은 OPEN_ISSUES 및 더 최근 일지를 함께 확인한다. #34~#43은 과거 작업의 식별 번호이며 현재 미해결 항목을 임의로 종료하지 않는다.
- 이 일지는 기존 문서의 개인정보·비밀번호·토큰을 복사하지 않는다.
