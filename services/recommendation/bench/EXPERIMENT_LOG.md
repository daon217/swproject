# LLM 입력 압축 실험 로그

목표: 코드가 안전·판매 판정을 먼저 끝내고, LLM 에는 "고르기 + 이유" 에 필요한 최소 정보만 보낸다.
토큰은 줄이되 추천 정확도는 유지한다. 측정한 것만 적는다.

## 실험 조건

- 데이터: `foods.bench.jsonl` 식품 24개 (실제 라벨 형식을 흉내 낸 **가상 데이터**), `queries.bench.json` 질의 8개와 정답 상품.
- 모든 방식에 같은 후보(알레르기 통과, 유사도 순 상위 12개, 같은 순서)를 넣고 형식만 바꿈.
- 지표
  - 크기: 시스템+사용자 메시지 UTF-8 바이트. 정확한 토큰 수는 LLM 실행 때 서버가 돌려주는 usage 로 기록.
  - 정보 보존율(LLM 없이): 각 후보의 번호·이름·가격·주요 원재료 3개·검색어 관련 원재료가 텍스트에 남았는지 비율.
  - 정확도(LLM): precision@3, recall@3 (정답 대비), 없는 번호를 지어낸 횟수.

## 비교 대상

| 방식 | 출처 | 아이디어 |
|---|---|---|
| json | 기존 랭커 | 필드 전체를 JSON 으로 |
| toon | [TOON](https://github.com/toon-format/toon-python) (`pip install toon-format`), MCP 서버로도 배포됨 | 같은 키를 표 머리글에 한 번만 쓰고 행만 나열 |
| llmlingua2 | [LLMLingua-2](https://arxiv.org/abs/2403.12968) (`pip install llmlingua`) | 작은 모델이 토큰마다 중요도를 매겨 덜 중요한 토큰을 삭제 |
| compact | 우리 (`compress.py`) | 아래 참고 |

### 우리 방식(compact)이 가져온 것

- TOON 에서: 열 이름을 반복하지 않는 표 형태. 한 걸음 더 나가서 열 정의를 **고정된 시스템 프롬프트**로 옮김
  (매 요청 같은 내용이라 서버 프롬프트 캐시에 걸리기 쉬움).
- LLMLingua 에서: "덜 중요한 정보는 버린다". 다만 모델로 토큰을 지우는 대신 **도메인 규칙**으로 지움
  (원재료는 함량 순이므로 앞 3개 + 검색어에 나온 원재료만, 흔한 첨가물 제외). 추가 모델·GPU 불필요.
- 자체: 긴 상품 id 대신 `c1..cN` 번호 → 코드에서 되돌림 (지어낸 번호는 자동 폐기). 이름이 같은 후보 중복 제거.
  안전 판정이 끝났으니 알레르기 표시·혼입 문구는 보내지 않음.

## 기록

### 1차 (2026-11-18, 클라우드, LLM 없이)

| 방식 | 사용자 메시지 바이트 | 전체 바이트 | JSON 대비 | 정보 보존율 |
|---|---|---|---|---|
| json | 3,457 | 4,593 | 1.00 | 1.000 |
| toon | 2,040 | 3,176 | 0.69 | 1.000 |
| compact (12개, 원재료 3) | 1,042 | 2,222 | 0.48 | 1.000 |
| compact8 (8개) | 717 | 1,897 | 0.41 | 1.000 |
| compact8_lean (8개, 원재료 2, 분류 없음) | 594 | 1,774 | 0.39 | 0.917 |

- llmlingua2: **측정 못 함**. 클라우드에서 모델 다운로드(Hugging Face)가 막힘. PC 에서 다시 시도 예정.
- 'JSON 대비'는 전체 바이트 기준 (시스템 프롬프트 포함). 사용자 메시지만 보면 compact 는 JSON 의 30%.
- 관찰: TOON 은 정보 손실 없이 31% 감소. compact 는 52% 감소, 보존율 유지. 더 줄이면(lean) 보존율이 떨어지기 시작.
- 아직 모름: 줄인 만큼 정확도가 유지되는지 → 2차(로컬 LLM)에서 측정.

### 2차 (2026-11-18 17:53 KST, 학교 LLM gemma-4-26b, 본인 PC, temperature 0)

결과 파일: `results/compression-20261118-175346.json`

- 40회 호출 중 **10회 실패**: q7·q8 은 모든 방식에서 서버 요청 제한(HTTP 429, 키당 30회)에 걸림.
  → 아래 정확도는 **성공한 q1~q6 (6개 질의)** 만으로 다시 계산. 토큰은 서버가 돌려준 실제 usage.
- 시행착오: 첫 두 번은 HTTP 403 (Python 기본 User-Agent 차단 추정 → User-Agent 지정 후 해결).

| 방식 | 입력 토큰 | JSON 대비 | precision@3 | recall@3 |
|---|---|---|---|---|
| json | 1,823 | 1.00 | 0.945 | 0.833 |
| toon | 1,230 | 0.67 | 0.945 | 0.833 |
| compact | 839 | 0.46 | 0.945 | 0.833 |
| compact8 | 683 | 0.37 | 0.945 | 0.833 |
| compact8_lean | 632 | 0.35 | 1.000 | 0.889 |

- 정정: 처음 집계(json 1,530 / compact 792 등)는 틀렸음. 요청 제한으로 실패한 호출에 직전 호출의 토큰 수가
  남아 평균에 섞였음. 실패 호출의 토큰 기록을 지우도록 고치고, 성공한 6개 질의만으로 다시 집계한 값이 위 표.
  방식별 원자료: `results/by_method/<방식>/20261118-175346.json`, 누적 표: `results/INDEX.md`.

- 관찰
  - 입력 토큰을 JSON 대비 35~46% 로 줄여도 6개 질의에서 정확도 손실 없음. 없는 번호를 지어낸 경우 0.
  - TOON 은 토큰 33% 감소, 정확도 동일. 우리 방식이 같은 정확도에서 토큰을 더 줄임.
  - compact8_lean 이 q1 하나에서 더 맞혔지만 질의 6개 중 1개 차이라 **우연일 수 있음** (반복 측정 필요).
  - q2(단백질 간식)는 모든 방식이 1개만 고름 → 압축 문제가 아니라 프롬프트/후보 문제. 다음 실험 대상.
- 다음: 요청 간격 2.5초로 q7·q8 포함 재측정, LLMLingua-2 (`pip install llmlingua`) 추가, 같은 조건 3회 반복.
